# Security / 安全报告

Do not publish secrets or private bundles in issues. If repository private vulnerability reporting is enabled, use **Security → Report a vulnerability**. Otherwise request a private contact without posting exploit details. No response-time guarantee is claimed.

Include the affected commit, a minimal reproduction, impact, and whether ownership, digest validation, exact amounts, quotas, or source verification is affected. Use disposable test data. Never run destructive checks against the public deployment or other people's reports.

请勿在公开 Issue 中发布凭据或私有原件。仓库启用私有漏洞报告时，使用 Security → Report a vulnerability；否则仅请求私下联系，不公开攻击细节。不承诺响应时限。

注明提交版本、最小复现和影响，尤其说明权限、摘要、金额、配额或来源核验是否受影响。使用一次性测试数据；不要对公共部署或他人报告做破坏性验证。
